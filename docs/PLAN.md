# 實作計畫

依 [DESIGN.md](DESIGN.md) 分階段實作。每個階段結束時跑離線測試（合成資料與 mock），並回報驗證了什麼、哪些還沒在真實信箱驗證。標示 ⛔ 的檢查點需要擁有者明確同意才繼續。

## 階段 0：專案骨架與隱私防護（2026-10-24 完成）

- Python 套件結構、`pyproject.toml`、`.env.example`、空的範例設定。
- 推送前隱私掃描腳本：比對 `.env` 的值與本機規則內容沒有出現在提交內容中，只輸出檔名與命中數。
- SQLite 結構：信件索引、寄件者群組、規則、待確認清單、動作紀錄。
- ⛔ 建立公開 GitHub repo 並首次推送。

## 階段 1：Outlook 讀取與索引（2026-10-24 完成，已對真實信箱唯讀同步）

- Graph 用戶端（參考舊專案的登入與移動前驗證，重寫成可同時支援 Gmail 的提供者介面）。
- 同步收件匣與寄件備份的描述資料到本機索引（不存內文），處理分頁與 token 更新。
- 客戶判定：寄件備份的收件人、聯絡人、客戶網域清單。
- 寄件者分組與統計。
- 本機訊號：沿用並擴充 `mail_signals`（群發佐證、保護訊號、驗證結果、可疑附件）。
- 參考舊專案的本機規則做為學習樣本（只在主機讀取，不進 repo）。

## 階段 2：規則引擎與執行層（程式完成；預覽已在真實索引上跑過，尚未移動任何信）

- 規則類型：寄件者地址、網域、網域＋主旨關鍵字；動作：歸檔到資料夾、移到垃圾桶、檢舉。
- 執行層集中實作硬性底線（受保護信件、無永久刪除、無寄信）與移動前驗證。
- 動作紀錄與還原（把信從垃圾桶或資料夾移回原處）。
- 自動建立「客戶」「個人」「收據」資料夾。
- 預覽模式（dry-run）：產生「會做什麼」的清單但不移動信件。

## 階段 3：PWA 介面

- 寄件者群組列表與手勢操作、待確認清單、規則管理、動作紀錄與一鍵還原。
- 安全閱讀檢視（純文字、連結不可點、附件只顯示描述資料）。
- PWA manifest 與 service worker（只快取介面，不快取信件資料）。
- 只綁定本機與 Tailscale 介面；寫入請求檢查來源與 CSRF。

## 階段 4：AI 分類與 MCP

- 規則草稿：Claude 透過 MCP 讀寄件者群組樣本（寄件者、主旨、分類），提出規則草稿進入待核准清單。
- Jev 逐封分類：遮蔽網址、電話與長數字後送前 1,500 字；套用門檻與群發佐證；低信心進待確認清單。
- 使用者確認後自動產生規則。
- MCP 伺服器（工具清單見 DESIGN.md 第 10 節），所有動作經過執行層。

## 階段 5：退訂、檢舉與封鎖

- RFC 8058 一鍵退訂與網址安全檢查；無法一鍵退訂時顯示網址。
- 退訂後處理舊信與建立封鎖規則。
- Outlook `reportMessage`（beta）與移到垃圾郵件的備案；Outlook 收件規則封鎖。

## 階段 6：Mac mini 部署

- launchd 常駐服務、`tailscale serve` HTTPS、每天 06:00 排程、每週日 21:00 Claude 檢查排程。
- 部署與更新腳本、日誌輪替。
- 擁有者需要：手機安裝 Tailscale、把 PWA 加到主畫面、完成 Outlook 首次登入。

## 階段 7：Outlook 試跑與整理

- ⛔ 以 50 個寄件者群組試跑，只預覽，擁有者確認結果。
- ⛔ 實測一封詐騙信的 `reportMessage` 行為。
- ⛔ 擁有者同意後，分批整理全部積信，每批可還原。

- ⛔ 同樣先以小批群組試跑再整理。
