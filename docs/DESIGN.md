# email-cleaner 設計

個人用的信箱清理工具：清掉 Outlook 與 Gmail 的垃圾信，保護客戶往來，學習規則後每天自動維持。原始碼公開；憑證、規則、信件索引與紀錄只存在執行主機本機。

## 1. 目標

- 一次清理既有積信（目標規模：Outlook 約 2 萬封、Gmail 約 1 萬封），之後每天自動維持。
- 支援 Outlook（Microsoft Graph）與 Gmail（Gmail API）。
- 不確定的信交給使用者確認；確認一次就產生規則，下次自動處理。
- 提供 MCP，讓 AI 定期整理。

## 2. 分類與處置

| 類別 | 判定方式 | 處置 |
| --- | --- | --- |
| 客戶往來（受保護） | 曾寄信給對方、在聯絡人中、或符合客戶網域清單 | 歸檔到「客戶」，永不移到垃圾桶 |
| 個人信件 | Jev／規則 | 歸檔到「個人」 |
| 帳單／收據／訂單 | 本機訊號＋Jev | 歸檔到「收據」 |
| 帳號與安全通知 | 本機訊號 | 30 天內保留，超過移到垃圾桶 |
| 系統通知、電子報、促銷、垃圾 | 規則＋Jev＋群發佐證 | 移到垃圾桶 |
| 詐騙／惡意附件 | 驗證結果、可疑附件、冒充訊號 | 檢舉＋建立封鎖規則 |

整理完成後，收件匣只留下最近 30 天尚未處理的信與待確認的信；其他保留的信歸檔到資料夾。Gmail 用標籤實作同一套結構。

客戶判定不交給 AI：只用寄件備份、聯絡人與客戶網域清單三種確定訊號。AI 只決定受保護的信放哪個資料夾。

## 3. 硬性底線

寫死在程式的執行層，任何呼叫者（網頁、排程、MCP）都不能違反：

1. 受保護的客戶信件不能移到垃圾桶。
2. 不永久刪除；刪除一律是移到垃圾桶（可復原）。
3. 不寄任何信，包括退訂；程式不申請寄信權限。

除此之外，MCP 可以執行所有動作（分類、移動、退訂、新增規則），每個動作都寫進動作紀錄，可一鍵還原。

每次移動前重新確認帳號、信件目前位置與內容快照，與舊專案的移動前驗證相同。

## 4. 分類流程與規則學習

**積信（一次性）**

1. 建立本機索引（只存描述資料，不存內文）。
2. 依寄件者分組，大量信件通常集中在少數寄件者。
3. Claude 只看寄件者、主旨樣本與 Gmail 分類（不看內文），產生「寄件者＋主旨關鍵字」規則草稿。
4. 使用者在介面上一鍵核准、修改或拒絕；核准後套用到整個群組。

**新信（每天）**

1. 先套用已核准的規則。
2. 沒有規則符合的才送 Jev。
3. Jev 自動處理門檻：群發判斷 ≥ 0.90、刪除判斷 ≥ 0.85，且需要群發佐證（`List-Unsubscribe`／`List-Id`／`Precedence` 標頭、退訂連結或電子報型寄件者）。
4. 低於門檻進入待確認清單；使用者確認後自動產生規則。

規則一律是可讀、可刪除的明文。規則單位預設為寄件者地址，確認時可升級為網域或「網域＋主旨關鍵字」。

**送給 Jev 的內容**：寄件者、主旨、標頭訊號、內文前 1,500 字；送出前遮掉網址、電話號碼與長數字（帳號、卡號、訂單號）。

## 5. 安全閱讀

- 只顯示純文字，不執行 HTML，不載入遠端圖片。
- 連結顯示為文字並標出真實網域，無法點擊。
- 附件不開啟、不下載、不解析內容，只顯示檔名、類型與大小，並標記可疑類型（雙副檔名、加密壓縮檔、含巨集的 Office 檔、可執行檔）。
- 顯示寄件者驗證結果（SPF／DKIM／DMARC）與顯示名稱冒充警示。

## 6. 檢舉與封鎖

- Outlook：呼叫 Graph `reportMessage`（目前僅 beta，需實測）；失敗時移到「垃圾郵件」。
- Gmail：加上 `SPAM` 標籤（Gmail API 無釣魚檢舉端點）。
- 兩者都另建封鎖規則（Outlook 收件規則、Gmail 篩選器），讓之後的來信自動進垃圾桶。
- 介面提供「開啟網頁版手動檢舉」按鈕，以進行正式通報。

## 7. 退訂

1. RFC 8058 一鍵退訂：標頭含 `List-Unsubscribe-Post: List-Unsubscribe=One-Click` 時，對 HTTPS 網址送出 POST。
2. 做不到時，顯示退訂網址讓使用者自行開啟。
3. 送出任何請求前做網址安全檢查：只允許 HTTPS、擋私有與保留 IP、限制轉址次數與回應大小、設定逾時。
4. 不使用 `mailto:` 退訂（不寄信）。
5. 退訂後，顯示該寄件者的舊信數量，確認後移到垃圾桶，並建立規則擋住之後的來信。

## 8. 執行環境與介面

- 執行主機：常駐的 Mac mini，只透過 Tailscale 存取，不對外公開；HTTPS 使用 Tailscale 提供的憑證以支援 PWA 安裝。
- 排程：每天 06:00 程式自行套用規則與 Jev；每週日 21:00 在主機上以 Claude Code 透過本機 MCP 做整理檢查。
- 介面：手機優先的 PWA，以寄件者群組為單位操作，支援手勢（左滑移到垃圾桶、右滑保留）。後台有待確認清單、規則管理、動作紀錄與一鍵還原。不做推播與摘要信。
- 技術：Python 單一程式提供網頁、API 與 MCP；SQLite 存信件索引、規則與動作紀錄；Gmail 走官方 API，OAuth 專案設為正式版（停在「測試中」狀態時，refresh token 7 天就會失效）。

## 9. 資料邊界

| 資料 | 位置 | 外送對象 |
| --- | --- | --- |
| Microsoft／Google OAuth token、TypeSafe API key | 主機 `data/` 與 `.env`（皆不進 Git） | 各自的服務 |
| 信件索引：寄件者、主旨、日期、資料夾、分類、標頭訊號 | 主機 SQLite | 不外送；Claude 撰寫規則時讀取寄件者與主旨 |
| 信件內文 | 不儲存，需要時即時向信箱讀取 | 遮蔽後的前 1,500 字送 TypeSafe Jev |
| 規則、動作紀錄 | 主機 SQLite | 不外送 |

公開 repo 只包含原始碼、合成測試資料、文件與空的範例設定。推送前檢查暫存的檔名與內容，並比對本機憑證與規則值不出現在提交內容中。

## 10. MCP 工具（草案）

- 讀取：`stats`、`list_sender_groups`、`list_review_queue`、`list_rules`、`get_action_log`
- 動作：`apply_rules`、`classify_pending`、`move_messages`、`create_rule`、`unsubscribe_sender`、`report_phishing`、`undo_action`

所有動作工具都經過第 3 節的底線檢查，並寫入動作紀錄。

## 11. 推出順序

1. Outlook 先上線：以 50 個寄件者群組試跑，只預覽不移動，使用者看過結果才開始真正整理。
2. Outlook 穩定後接 Gmail。
3. 新系統穩定後，封存舊的 `jev-outlook-cleaner`；舊的每日排程維持暫停。

## 12. 已知未驗證事項

- Graph `reportMessage` 是否在 outlook.com 個人帳號有效，以及是否真的送出檢舉。
- Gmail API 加上 `SPAM` 標籤是否被 Google 視為檢舉。
- outlook.com 的 `internetMessageHeaders` 是否包含 `Authentication-Results`。
- TypeSafe 帳號的實際速率限制（只在後台可見）；TypeSafe 會保存送出的內容（不用於訓練），保存期間未公開。
